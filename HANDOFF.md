## Refresh and background processing

`packages/db/src/monitoring.ts` coordinates a PostgreSQL shared/exclusive session advisory gate. Supported analytic writers mark readiness dirty before mutation. A watch acquires the shared gate before beginning its repeatable-read snapshot; a later failed/running refresh blocks new checks rather than borrowing an older ready checkpoint.

`pnpm --filter ingestion monitoring-refresh --run` performs the coordinated normalize/reconcile/TED/marts/flags/Radiografie/coverage pipeline and complete validation. It does not collect from the network. `--validate-existing` validates an already completed snapshot without rebuilding or inventing collection timestamps. Raw Graphile scraping jobs do not publish an analytic checkpoint. Direct SQL or low-level custom writers outside the gate are unsupported.

Local existing-data checkpoint **a888f7f9-f39f-4b23-9c1e-0ffefe46270d**, version1, is ready after ten full checks (~128seconds). Actual source dates remain older (latest observed DA July16, contracts July9, TED June30); validation on September19 is not fresh collection. Do not unnecessarily repeat the expensive Batch1 refresh.

The standalone worker reconstructs pending work from persisted watch/checkpoint state and resumes after restart. One watch/checkpoint produces one complete run; failures preserve the last successful observation. Global owner health includes watches awaiting the current checkpoint, not just never-checked watches or the first page. Paused watches are excluded. Monitoring reads source coverage within its current snapshot, avoiding the ordinary request coverage cache.

Key files: `lib/monitoring-{input,shared,identity,engine,case,api}.ts`, `lib/monitoring.ts`, `/api/urmariri`, `scripts/monitoring-worker.ts`, `scripts/check-monitoring.ts`; digest engine/CLI separate. UI under `app/urmariri`, shared `components/FollowButton.tsx` and case integrations in `DossierEvidence.tsx` / `CaptureStatus.tsx`.
