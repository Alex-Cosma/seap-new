## Procedura acestei lansări

Tranziția calendarului `rf-2026.6` cere backup și un full înaintea redeschiderii. Scripturile datate `scripts/operations/calendar-release-20260930.{sh,mjs}` sunt proceduri one-off, nu cron/setup. Fazele shell cer SHA exact și checkout curat, folosesc lockul comun cu deploy/cron. Pregătirea cere rev20 observată și starea verificată; redeschiderea cere rev21, același boundary și ultimul checkpoint validat. Orice eroare păstrează mentenanța. Nu se rescrie rularea daily de azi și nu se inventează o zi programată pentru această intervenție manuală; progresul are worker, checkpoint și jurnal proprii.

1. `prepare <old SHA>`: pauză/mentenanță auditată, drain, raw boundary, backup complet privat/listă/SHA256. Workerii rămân porniți dar blocați de poartă, pentru a păstra profilul collection activ la deploy.
2. Commit/push normal pe main; CI/deploy construiește imaginile, aplică0042–0045, granturi și Caddy înaintea înlocuirii web. Mentenanța rămâne activă.
3. `publish <release SHA>`: checksum backup, oprire workeri deja drenați, refresh full la boundary fix, validări complete, reconstruire topic search și Meili, verificarea celor două contracte cunoscute și a unui contract la trecerea dintre ani. Fără colectare SEAP.
4. Inspectarea raportului, apoi `reopen <release SHA>`: restart pentru cache-uri, health, verificări atomice pentru checkpoint/control/boundary, redeschidere și reluarea workerilor existenți. Programul rămâne daily plus risc duminică.
